### Root cause

This caused the GTK build to fail silently.

### Fix
In `gui_loop.sh:94-97`, changed from storing the literal `'$HOME/.cargo/bin/cargo'` to resolving the path inside WSL immediately via `$(wsl bash -c 'echo "$HOME/.cargo/bin/cargo"')`. This produces an absolute path (e.g., `/home/user/.cargo/bin/cargo`) that works correctly in all subsequent double-quoted contexts.

### Why 146 prior attempts missed this

  2. `command -v cargo` fails inside WSL (non-interactive shell)

## 2026-07-01 (current session): Fixed GTK4 cell edit returning no recording output — `GtkEntry` internal controller consumes Enter before `on_key_raw` fires

### Root cause
The `rec_CellEdit` test scenario checks that editing a cell on the GTK backend produces recording output (appended `.corro` file lines). On GTK4, `GtkEntry`'s internal `GtkEventControllerKey` (CAPTURE phase) consumes the RETURN key: it emits `activate` and returns `GDK_EVENT_STOP` **before** our externally-added `GtkEventControllerKey` (default BUBBLE phase) in `Entry::on_key_raw` ever fires. As a result, `handle_key` → `commit_edit` is never called, and no recording output is produced.

On GTK3, the "key-press-event" signal handler in `on_key_raw` is connected with `g_signal_connect` (runs before the default handler), so our callback fires for RETURN and returns `GDK_EVENT_STOP` to prevent the entry from processing it. On NWG (Windows), Win32 subclassing intercepts all keys. Only GTK4 has the issue.

### Changes Made

**`rustxwidgets/src/backends_gtk_adapter_impl.rs`** (HIGH — `Entry::on_key_raw` GTK4 path):
- Wrapped the callback in `Rc<RefCell<Option<Box<dyn FnMut(u32, u32) -> bool>>>>` so it can be shared between two handlers.
- Kept the existing `EventControllerKey` for printable characters (which the entry does NOT consume — it returns `GDK_EVENT_STOP` only for IM-handled keys).
- **Added `connect_activate` handler** on the entry. On GTK4, `GtkEntry` emits `activate` synchronously **before** its internal controller returns `GDK_EVENT_STOP`. Our handler invokes the same `on_key_raw` callback with `(0xFF0D, 0)` (VK_RETURN), which triggers `handle_key` → `commit_edit` → `commit_workbook_op` → file output.

### Design guidance followed
Extended `rustxwidgets` (the GTK adapter) to abstract the backend difference. No platform-specific `#[cfg]` blocks were added in `src/gui/`. The `gui_backend.rs` code uses only `rustxwidgets::prelude::*` and is unchanged.
